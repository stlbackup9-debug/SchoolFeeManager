# Application Architecture

## Technology choice

| Need | Choice | Why |
|---|---|---|
| Android APK **and** desktop from one codebase | Web app (React + TypeScript), packaged with **Capacitor 7** for Android and as a **single self-contained HTML file** for desktop | One tested codebase; Android WebView and desktop Chrome/Edge both use Chromium |
| Local, reliable database | **SQLite** via sql.js (WebAssembly) | Real SQLite with transactions and CHECK constraints; the backup is a standard `.sqlite` file |
| Offline | All code, the WASM engine and the Myanmar font are bundled | No network needed at any point |
| Myanmar Unicode | Bundled **Noto Sans Myanmar** font; PDF generated by rendering HTML with the browser's text shaper | Correct rendering of stacked Myanmar characters, including in PDF files |
| Excel | **SheetJS** (`xlsx`), write-only | Real `.xlsx` with numeric cells and number formats |
| PDF | **html2canvas + jsPDF** | Same layout as print; page breaks at table rows |

## Layers

```
┌─────────────────────────── UI (src/ui) ───────────────────────────┐
│ App (routing, theme, language, toasts, confirm dialogs)            │
│ Dashboard · EntryPage/EditRecordModal · RecordsPage · ReportsPage │
│ HistoryPage · SettingsPage · shared Components / RecordsTable      │
└──────────────┬───────────────────────────────┬────────────────────┘
               │                               │
   src/lib (pure logic)              src/db (data access)
   validation.ts  input rules        repo.ts      Repo: CRUD, duplicates, filters,
   dates.ts       date maths                      totals, reports queries, history,
   format.ts      number format                   settings; emits change events
   i18n.ts        EN / MY text       database.ts  Db wrapper over sql.js, migrations,
   reports.ts     ReportDoc builder               transactions, backup validation
                  + HTML renderer    schema.ts    DDL + version
   export.ts      xlsx / pdf / print storage.ts   IndexedDB persistence, AutoSaver,
                  / file save                     daily snapshots
                                     sample.ts    deterministic sample data
```

Data flow:
1. `main.tsx` loads the saved database bytes from IndexedDB → `Db.create()` (runs migrations) → `Repo`.
2. UI pages call `Repo` methods. Every write is validated (`normalizeInput`), runs in a transaction, is logged to `history` and fires `onChange`.
3. `onChange` → the UI re-renders (version counter) and the `AutoSaver` writes the database file to IndexedDB.
4. Reports: `buildReport()` produces one `ReportDoc` (sections of columns/rows/totals). The same object is rendered on screen, printed, turned into a PDF and written to Excel, so all outputs show identical numbers.

## Platform specifics
- **Android**: file outputs (Excel/PDF/backup) are written to the app cache and opened in the Android share sheet (with a copy in `Documents/2D3D` where permitted). *Print* creates a PDF, because Android WebView cannot print directly. The hardware back button navigates back between pages. The database is flushed when the app is paused.
- **Desktop**: files download normally and *Print* uses the browser print dialog with print-only CSS (A4).
